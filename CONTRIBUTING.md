# Как доработать программу

Исходники лежат прямо в скачанном пакете, в папке `app`. Это обычные
текстовые файлы — открываются любым редактором, правятся и работают
сразу. Ничего собирать и компилировать не нужно.

---

## Самый быстрый путь

1. Распакуйте пакет
2. Откройте `app\webui.py` или `app\ui.html` в редакторе
3. Поправьте
4. Закройте окно программы и запустите `START_GUI.bat` заново

Всё. Python уже внутри пакета, в папке `python`, и запускает
именно ваши файлы.

Для правки подойдёт любой редактор: Блокнот, Notepad++, VS Code.
Сохраняйте **в кодировке UTF-8** — файлы уже в ней, большинство
редакторов сохранят правильно автоматически.

---

## Что где лежит

| Хочу поменять | Файл |
|---|---|
| Внешний вид, тексты, вкладки | `app/ui.html` |
| Логику кнопок и разделов | `app/webui.py` |
| Описания кодов неисправностей | `app/pdc_codes.py` |
| Живые параметры двигателя | `app/pdc_obd.py` |
| Работу с адаптером и протоколом | `app/pdc_core.py` |
| Текстовое меню | `app/menu.py`, `app/pdc_diag.py` |

Подробная карта модулей и точки расширения — в файле
[ARCHITECTURE.md](ARCHITECTURE.md).

## Проверка правок без автомобиля

В комплекте заглушка, изображающая автомобиль. Два окна командной
строки в папке программы:

```
python\python.exe app\mock_elm327.py 35003 --glitch
```

```
python\python.exe tests\test_smoke.py
```

Тесты проверяют разбор кадров, сборку длинных ответов, расшифровку
кодов и полный обмен. **Прогоняйте их после каждой правки** — они
ловят ровно те поломки, которые незаметны глазом: программа продолжает
работать, но выдаёт неверные данные.

Для проверки интерфейса подключитесь в программе к `127.0.0.1:35003`.

## Если ставите Python отдельно

Подойдёт версия 3.8 и новее, ничего доустанавливать не нужно:

```
git clone <адрес репозитория>
cd vagdiag
python app/webui.py
```

Папка `python` из пакета в этом случае не требуется.

## Что хотелось бы получить

Приветствуется всё, но особенно:

**Отчёты с других автомобилей.** Файл `REPORT_TO_SEND.txt` с любой
машины — это адреса блоков, их имена и особенности протокола.
Из таких отчётов складывается справочник «модель → блоки», которого
в открытом виде не существует. Приложите его к обращению по шаблону
«Отчёт с автомобиля».

**Описания кодов.** Если знаете точное значение кода производителя
для конкретной модели — добавьте в `pdc_codes.py`. Это самая
востребованная и самая недостающая часть.

**Поддержка протокола TP 2.0.** Автомобили VAG примерно до 2010 года
используют другой протокол, который здесь не реализован. Это большая
работа, но она открыла бы программу для огромного числа машин.

**Сведения об адаптерах.** Если ваш ELM327 **умеет** дочитывать длинные
ответы от блоков кузовной электроники — обязательно напишите, какая
это модель и версия. Мы такого не встречали, и это важное знание.

**Переводы.** Словарь в `ui.html`, объект `I18N`. Добавить язык —
значит дописать один блок пар «русская строка — перевод».

## Правила

- Внешние библиотеки не добавляем: пакет должен работать сразу
  после распаковки
- Комментарии объясняют, **почему** так сделано
- Особенности поведения железа сопровождаются пояснением, иначе
  следующий человек уберёт их как лишние
- Ничего не пишем в блоки без явного согласия пользователя:
  программа читающая, единственное исключение — стирание ошибок
  по кнопке с подтверждением

---

## Присылать правки

Обычным образом: ответвление, ветка, изменения, запрос на слияние.
В описании укажите, на чём проверяли — на заглушке или на живом
автомобиле, и на каком именно.

Тесты запускаются автоматически при каждом запросе на слияние.
