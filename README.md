# VAG Diag — диагностика автомобилей группы VAG адаптером ELM327

[English version](README.en.md)

Программа читает ошибки блоков управления Volkswagen, Škoda, SEAT и Audi
через дешёвый адаптер ELM327 по Wi-Fi. Работает на Windows без установки
Python и без единой внешней библиотеки. Интерфейс открывается в браузере.

Изначально написана для поиска обрыва в проводке парктроника VW Polo Sedan,
когда обычные приложения показывали только двигатель, а блок парковочной
системы оставался недоступен. Выложена в надежде, что кому-то ещё пригодится.

## Что умеет

| Возможность | Описание |
|---|---|
| Поиск блоков | Перебор адресов, находит все отвечающие блоки автомобиля |
| Идентификация | Имя блока и номер запчасти по каждому найденному |
| Чтение ошибок | Количество ошибок, код и **тип отказа** — обрыв, замыкание, нет связи |
| Разбор по признакам | Активна сейчас, подтверждена, была ранее — по каждому признаку отдельно |
| Стирание ошибок | Очистка памяти выбранного блока |
| **Монитор ошибок** | Живой счётчик для поиска неисправного датчика отключением |
| **Двигатель OBD-II** | Коды, готовность систем, VIN, стоп-кадр — на любом автомобиле |
| **Живые параметры** | Обороты, температуры, нагрузка, напряжение с записью в файл |
| **Мастер поиска датчика** | Пошаговый протокол «отключил — записал», строит карту код↔датчик |
| Полное сканирование | Одна кнопка: поиск, сбор, разбор, отчёт |
| **Сравнение до и после** | Снимки состояния и разбор: что ушло, осталось, появилось |
| **Тест аккумулятора и генератора** | График напряжения при пуске с автоматическим выводом |
| **Описания кодов** | Офлайн-словарь стандартных кодов OBD-II |
| Отчёт | Текстом с полным обменом и отдельно страницей для печати |

### Поддерживаемые адаптеры

| Тип | Как подключается | Особенности |
|---|---|---|
| ELM327 Wi-Fi | по сети, обычно `192.168.0.10:35000` | самый распространённый |
| ELM327 USB | через COM-порт | тот же протокол, стабильнее связь |
| ELM327 Bluetooth | через COM-порт после сопряжения | удобно с ноутбуком |
| **USB-CAN (SLCAN)** | через COM-порт | **читает длинные списки ошибок целиком** |

Последний снимает главное ограничение — см. раздел «Ограничения».

### Чего не умеет

- Не кодирует блоки, не меняет настройки, не выполняет адаптации.
  Всё только на чтение, кроме явного стирания ошибок по кнопке.
- Не показывает текстовые описания кодов из базы производителя —
  выводится номер кода и стандартный тип отказа по ISO 14229-1.
- Не читает длинные списки ошибок целиком на дешёвых адаптерах —
  см. раздел «Ограничения».

## Быстрый старт

1. Скачать архив из раздела Releases и **распаковать в отдельную папку**
2. Вставить адаптер в разъём OBD, обычно под рулём слева
3. **Включить зажигание, двигатель не запускать**
4. Подключить компьютер к сети Wi-Fi адаптера
5. Запустить `START_GUI.bat` — откроется браузер с интерфейсом
6. Нажать «Подключиться», затем вкладка «Блоки» → «Быстрый поиск»

Python устанавливать не нужно, он входит в архив. Права администратора
не требуются.

Если Windows покажет «Защитник Windows заблокировал запуск» — нажать
«Подробнее», затем «Выполнить в любом случае». Так система реагирует
на любой bat-файл, скачанный из интернета.

## Интерфейс

### Подключение
Адрес и порт адаптера. По умолчанию `192.168.0.10:35000` — подходит
большинству китайских адаптеров. Свой адрес можно посмотреть в свойствах
подключения Wi-Fi как «шлюз по умолчанию». Другие частые варианты:
`192.168.4.1` и `192.168.1.10`.

Программа сразу показывает напряжение бортсети и предупреждает,
если оно ниже 11,5 В (блоки начнут выдавать ложные ошибки)
или выше 13,3 В (двигатель запущен, лучше заглушить).

### Блоки
**Быстрый поиск** проверяет известные адреса блоков VAG, занимает
полминуты. **Полный поиск** перебирает все 256 адресов диапазона —
дольше, но найдёт нестандартные блоки.

**Собрать данные по всем** опрашивает каждый найденный блок:
имя, номер запчасти, количество ошибок и первый код.

Кнопка **Ошибки** напротив блока даёт разбор по признакам.
Кнопка **Стереть** очищает память ошибок с подтверждением.

### Двигатель
Универсальный раздел, работает **на любом автомобиле с 2001 года**, не только
VAG: стандартные режимы OBD-II обязательны по закону об выбросах.

Читаются сохранённые, неподтверждённые и постоянные коды с расшифровкой
категории, состояние лампы неисправности, VIN, стоп-кадр с условиями
появления ошибки и готовность систем самодиагностики.

Готовность важна перед техосмотром: непройденные тесты завалят его даже
при отсутствии ошибок. После стирания кодов все тесты сбрасываются
и требуют нескольких десятков километров пробега в разных режимах.

### Живые параметры
Программа сама спрашивает у двигателя, какие параметры он поддерживает,
и опрашивает только их. Обороты, температуры охлаждающей жидкости, воздуха
и масла, нагрузка, дроссель, расход воздуха, уровень топлива, напряжение.
Всё пишется в `live_log.csv` с метками времени.

### Мастер поиска датчика
Пошаговый протокол для построения карты «датчик — код ошибки».
Отключаете один датчик, подписываете шаг его названием, нажимаете
«Снять показание». Программа фиксирует число активных ошибок, изменение
относительно предыдущего шага и код, который появился.

После обхода всех датчиков получается таблица соответствия — становится
понятно, какому датчику принадлежат коды, висящие в памяти постоянно.
Справочники с распиновкой при этом не нужны: карта строится
экспериментально для конкретного автомобиля.

### Сравнение до и после
Снимок запоминает, какие ошибки и в каком количестве были в этот момент.
Сделайте снимок до ремонта и после — программа покажет три списка:
что ушло, что осталось и что появилось, а по блокам ещё и динамику
количества.

Это главный вопрос при ремонте, и по памяти на него не ответить.
Снимки лежат в папке `history` и никуда не исчезают.

### Тест аккумулятора и генератора
Программа часто опрашивает напряжение бортовой сети и строит график.
Нажмите «Начать замер» при заглушенном двигателе, через пару секунд
запустите его.

Глубина просадки при пуске говорит о состоянии аккумулятора и цепи
стартера, напряжение на работающем двигателе — о генераторе и его
регуляторе. Программа сама выдаёт заключение по обоим значениям.
Отдельный прибор для этого не нужен.

### Монитор
Живой счётчик активных ошибок. Придуман для задачи «какой из восьми
датчиков парктроника неисправен» и решает её за десять минут
без снятия бампера:

1. Зажигание включено, двигатель заглушен, **задняя передача включена** —
   без неё блок датчики не опрашивает и счётчик не сдвинется
2. Отключить все датчики бампера, запустить монитор, запомнить число
3. Подключать датчики по одному, после каждого ждать 10–15 секунд
4. Счётчик уменьшился — канал исправен. Не сдвинулся — вот дефект

### Отчёт
Кнопка «Сохранить отчёт» создаёт `REPORT_TO_SEND.txt` рядом с программой:
версия, время, все найденные блоки, разборы ошибок, история монитора
и **полный обмен с адаптером** — каждая посланная команда и каждый ответ.
Один файл, который можно приложить к вопросу на форуме.

## Как читать результат

### Тип отказа — что искать

| Тип отказа | Где искать |
|---|---|
| обрыв цепи | прозванивать жилу, проверять разъём и пины |
| замыкание цепи на массу | проверять изоляцию проводки |
| замыкание цепи на плюс | искать протёртую изоляцию рядом с силовой цепью |
| нет сообщений от узла | проверять питание и массу узла |
| сигнал нестабилен | плохой контакт, искать шевелением жгута |

### Состояние ошибки — как искать

| Состояние | Что означает |
|---|---|
| активна сейчас | дефект присутствует, можно искать замерами |
| подтверждена | блок зафиксировал дефект как достоверный |
| была ранее | плавающий дефект, искать шевелением проводки |

Состояние важнее номера кода. «Активна сейчас» ищется мультиметром прямо
сейчас; «была ранее» означает нестабильный контакт, и тут помогает
провокационный тест — шевелить жгут, наблюдая за прибором.

## Ограничения

### Дешёвые адаптеры ELM327 не читают длинные ответы

Прошивка ELM327 умеет вести многокадровый обмен только с парой адресов
двигателя (`0x7E0` → `0x7E8`), зашитой в неё намертво. Блоки кузовной
электроники отвечают с другим смещением — например, `0x70A` отвечает
с `0x774`, — и адаптер не запрашивает у них продолжение длинного ответа.

Обойти это командами не выходит. Проверено:

| Способ | Результат |
|---|---|
| `ATCRA` + `ATFCSH` + `ATFCSD` + `ATFCSM1` | команды принимаются, продолжение не запрашивается |
| `ATCAF0` и ручная отправка кадра разрешения | адаптер добавляет свой служебный байт поверх нашего |
| `ATAR` | заставляет ждать ответ по правилу «запрос плюс восемь» |
| `ATCRAXXX` | клоны отвечают `?` — команда не поддерживается |

Доказательство подмены кадра: при отправке `03 22 F1 97` блок принимает
за номер сервиса `0x03`, то есть наш счётчик длины. Кадр разрешения
начинается с байта `0x30`, который сам является служебным, — адаптер
приписывает перед ним свой, и получается мусор.

**Что программа делает вместо этого.** Заявленная длина ответа берётся
из заголовка первого кадра, поэтому **количество ошибок определяется
точно**. Первая запись списка приходит целиком, поэтому виден её код
и тип отказа. Фильтрация по признаку меняет состав списка, и первым
оказывается разный код — так вытаскивается несколько кодов вместо одного.

**Решение уже встроено.** Выберите тип адаптера «USB-CAN, протокол SLCAN»
и подключите адаптер CANable, CANtact или совместимый. Он отдаёт сырые
кадры шины, а сборку ISO-TP и отправку кадра разрешения программа делает
сама — длинные списки читаются целиком. Такой адаптер стоит примерно
как обычный ELM327.

### Прочее

- Поддерживается только протокол UDS поверх CAN, 11-битные адреса.
  Протокол TP 2.0 (более ранние автомобили) не реализован.
- Дешёвые адаптеры перестают отвечать после нескольких десятков команд
  подряд. Программа замечает череду пустых ответов и перезапускает адаптер
  сама, но если это не помогло — выньте его из разъёма на 10 секунд.
- Некоторые блоки не поддерживают чтение имени или номера запчасти.
  Это нормально и не означает неисправность.

## Консольная версия

Кроме интерфейса в браузере есть текстовое меню: `START.bat`.
В нём те же функции плюс несколько узкоспециальных режимов:

| Пункт | Режим |
|---|---|
| 1 | Поиск блоков |
| 2–3 | Чтение и стирание ошибок |
| 4 | Идентификация блока |
| 5–6 | Поиск и просмотр живых данных |
| 7 | Провокационный тест — ловит момент пропадания контакта |
| 8 | Проверка на заглушке, без автомобиля |
| 10 | Полный отчёт по всем блокам |
| 11 | Детальный опрос с выводом сырых байт |
| 12 | Целевой опрос одного блока с подбором способа передачи |
| 13 | Стирание и повторное чтение |
| 14 | Монитор ошибок |

Все режимы доступны и напрямую:

```
python app\pdc_diag.py scan
python app\pdc_diag.py dtc --id 70A
python app\pdc_diag.py monitor --id 70A
```

## Проверка без автомобиля

В комплекте заглушка адаптера, изображающая блок парктроника
с плавающим контактом. Позволяет убедиться, что всё установлено
и работает, не выходя из дома.

```
python app\mock_elm327.py 35003 --glitch
```

Затем в интерфейсе подключиться к `127.0.0.1:35003`, либо в консольном
меню выбрать пункт 8.

## Как это устроено

```
Интерфейс в браузере
   ↕ локальный HTTP на 127.0.0.1:8765
Сервер на Python
   ↕ TCP-сокет на 192.168.0.10:35000
Адаптер ELM327 Wi-Fi
   ↕ шина CAN
Блоки управления автомобиля
```

Прикладной протокол — UDS (ISO 14229). Используются сервисы:

| Сервис | Назначение |
|---|---|
| `3E` TesterPresent | проверка связи, поиск блоков |
| `10` DiagnosticSessionControl | открытие расширенной сессии |
| `22` ReadDataByIdentifier | имя блока, номер запчасти, живые данные |
| `19 02` ReadDTCInformation | список ошибок с фильтром по признаку |
| `14` ClearDiagnosticInformation | стирание памяти ошибок |

## Исходники внутри пакета

**Программа поставляется вместе с исходниками.** Всё, что в папке `app`, —
обычные текстовые файлы на Python и один файл разметки. Их можно открыть
блокнотом, поправить и запустить: ничего собирать и компилировать не нужно,
Python лежит рядом в папке `python`.

Порядок такой:

1. Открыть `app\ui.html` или `app\webui.py` в любом редакторе
2. Поправить
3. Закрыть окно программы и запустить `START_GUI.bat` заново

В комплекте есть `DEV_TOOLS.bat` — открывает папку с исходниками,
запускает автотесты и заглушку адаптера для проверки правок без автомобиля.

| Хочу поменять | Файл |
|---|---|
| Внешний вид, тексты, вкладки | `app/ui.html` |
| Логику кнопок и разделов | `app/webui.py` |
| Описания кодов неисправностей | `app/pdc_codes.py` |
| Живые параметры двигателя | `app/pdc_obd.py` |
| Работу с адаптером и протоколом | `app/pdc_core.py` |

Подробности: [ARCHITECTURE.md](ARCHITECTURE.md) — карта модулей, поток
данных и точки расширения. [CONTRIBUTING.md](CONTRIBUTING.md) — как
проверять правки и что хотелось бы получить.

## Разработка

Автотесты гоняются на встроенной заглушке, автомобиль не нужен:

```
python tests/test_smoke.py
```

Проверяются разбор кадров, сборка многокадровых ответов, расшифровка

## Предупреждение

Программа работает с бортовой электроникой автомобиля. Хотя все операции,
кроме явного стирания ошибок, выполняются только на чтение, автор
не несёт ответственности за последствия использования.

Не пользуйтесь программой во время движения. Диагностика выполняется
на стоящем автомобиле с включённым зажиданием и заглушенным двигателем.

Стирание ошибок удаляет историю неисправностей. Перед стиранием
сохраните отчёт — восстановить стёртые записи невозможно.
