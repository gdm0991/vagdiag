# Устройство программы

Документ для тех, кто хочет что-то поменять. Внешних библиотек нет
нигде — только стандартная поставка Python. Это осознанное ограничение:
пакет должен работать сразу после распаковки, без установки чего-либо.

---

## Карта модулей

```
START_GUI.bat ──> app/webui.py ──> app/ui.html
                       │
                       ├── app/pdc_core.py     транспорт, ISO-TP, UDS
                       ├── app/pdc_obd.py      стандарт OBD-II
                       ├── app/pdc_codes.py    словарь описаний кодов
                       ├── app/pdc_serial.py   COM-порт

START.bat ────> app/menu.py ────> app/pdc_diag.py ──> app/pdc_core.py

tests/test_smoke.py ─> app/mock_elm327.py   заглушка вместо автомобиля
```

| Файл | За что отвечает |
|---|---|
| `pdc_core.py` | Связь с адаптером, сборка кадров ISO-TP, клиент UDS, расшифровка кодов, отчёты |
| `pdc_obd.py` | Стандартные режимы OBD-II: коды двигателя, живые параметры, готовность, VIN |
| `pdc_codes.py` | Офлайн-словарь описаний кодов и разбор структуры номера |
| `pdc_serial.py` | Последовательный порт с интерфейсом сетевого сокета |
| `pdc_slcan.py` | USB-CAN адаптер с интерфейсом класса `Elm327` |
| `pdc_diag.py` | Режимы работы и разбор командной строки |
| `menu.py` | Текстовое меню |
| `webui.py` | Локальный веб-сервер, очередь задач, состояние |
| `ui.html` | Вся страница: разметка, оформление, логика, перевод |
| `mock_elm327.py` | Заглушка адаптера: изображает блоки и умеет ломаться нарочно |

## Главный приём: подмена интерфейса

По всей программе используется один и тот же приём — новый способ связи
притворяется старым, и остальной код не меняется вовсе.

**Уровень канала.** `SerialChannel` повторяет методы сетевого сокета:
`sendall`, `recv`, `settimeout`, `close`. Поэтому `Elm327` работает через
COM-порт, ничего не зная об этом:

```python
elm = Elm327(host, port)
elm.sock = SerialChannel("COM3", baudrate=38400)   # вместо сокета
elm.init()                                          # дальше как обычно
```

**Уровень адаптера.** `SlcanAdapter` повторяет методы `Elm327`: `cmd`,
`set_header`, `accept_all`, `identify`. Его `cmd()` принимает запрос
в том же виде и **возвращает ответ строками того же формата**, раскладывая
собранные данные обратно в кадры. Благодаря этому весь разбор в программе
остаётся общим, хотя внутри работает совсем другой протокол.

Если будете добавлять новый тип адаптера — повторяйте этот приём,
он экономит огромное количество правок.

## Поток данных

```
кнопка в браузере
   ↓ POST /api/что-то
Handler.do_POST          разбирает запрос
   ↓
Engine.start(...)        ставит задачу в очередь, одну за раз
   ↓
метод движка            работает в отдельном потоке
   ↓
UdsClient / pdc_obd      формирует запросы протокола
   ↓
Elm327 / SlcanAdapter    обмен с железом
   ↓
Engine.state             результат складывается в состояние
   ↓ GET /api/state каждые 0,8 с
страница перерисовывается
```

Задачи выполняются строго по одной: адаптер один, параллелить нечего.
Долгие операции сообщают о ходе через `self.progress`.

## Точки расширения

### Добавить живой параметр OBD-II

В `pdc_obd.py`, словарь `PIDS`. Ключ — номер параметра, значение —
название, единица и формула пересчёта из сырых байт:

```python
0x0E: ("Опережение зажигания", "°", lambda d: _u8(d) / 2 - 64),
```

Больше ничего менять не нужно: интерфейс сам подхватит новый параметр,
если двигатель сообщит о его поддержке.

### Добавить описание кода

В `pdc_codes.py`, словарь `KNOWN`. Ключ — код, значение — описание
на русском. Коды производителя туда же, если знаете точное значение.

### Добавить тип отказа

В `pdc_core.py`, словарь `FAILURE_TYPE`. Ключ — третий байт кода
по стандарту ISO 14229-1.

### Добавить режим в текстовое меню

1. Функция `mode_имя(args)` в `pdc_diag.py`
2. Регистрация в `build_parser()`
3. Пункт в `ACTIONS` и в выводе меню в `menu.py`

### Добавить раздел в интерфейс

1. Метод в классе `Engine` в `webui.py`
2. Маршрут в словаре `actions` в `Handler.do_POST`
3. Поле в `Engine.snapshot()`, чтобы результат попал на страницу
4. Вкладка и функция отрисовки в `ui.html`

### Добавить язык интерфейса

В `ui.html`, объект `I18N`. Ключ — русская строка, значение — перевод.
Перевод применяется обходом текстовых узлов страницы, размечать
разметку не требуется.

## Особенности, которые дорого дались

Эти вещи выяснены опытным путём на живом автомобиле. Не убирайте их,
не проверив: каждая закрывает конкретную поломку.

| Место | Почему так |
|---|---|
| Чистка буфера перед каждой командой | Иначе ответ одного блока читается как ответ следующего, и имена блоков перемешиваются |
| Минимум служебных команд перед запросом | Дешёвый адаптер захлёбывается: после десятка команд подряд начинает возвращать пустоту |
| Снятие фильтра через `ATCF000` + `ATCM000` | `ATAR` заставляет ждать ответ по правилу «запрос плюс восемь», `ATCRAXXX` клоны не понимают |
| Повтор при ответе «занят» (код 0x21) | Блок остаётся занят после незавершённой длинной передачи примерно на секунду |
| Пауза 2 секунды между выборками ошибок | По той же причине |
| Заявленная длина берётся из заголовка | Позволяет знать число ошибок даже когда список не дочитан |
| Расширенная сессия перед стиранием | Без неё блок отвечает отказом |
| Отслеживание ответа `?` | Непонятая команда молча не выполняется, и программа работает на неверных допущениях |

## Заглушка адаптера

`mock_elm327.py` изображает автомобиль по сети. Умеет:

- отвечать как ELM327 на служебные команды;
- изображать блок парктроника с ошибками;
- изображать блок кузовной электроники, который отдаёт длинный ответ
  **только после кадра разрешения** — так воспроизводится главная
  особенность настоящих блоков;
- отвечать на стандартные запросы OBD-II;
- с ключом `--glitch` периодически «терять» датчик — для проверки
  монитора ошибок.

```
python app/mock_elm327.py 35003 --glitch
```

Затем подключиться к `127.0.0.1:35003`.

## Стиль кода

- Комментарии и сообщения на русском, имена — латиницей
- Комментарий объясняет **почему**, а не что: «что» видно из кода
- Строки до 88 символов
- Никаких внешних зависимостей, только стандартная библиотека
- Каждая новая особенность железа — с пояснением в комментарии,
  иначе следующий человек её уберёт как лишнюю
